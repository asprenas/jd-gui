# 작업지시서: UI 및 디컴파일 영역 글꼴 설정\n\n기준 계획: [work-plan-ui-font-settings.md](work-plan-ui-font-settings.md)\n작성일: 2026-10-26\n\n## 작업 목표\n\n환경 설정의 `Viewer > Appearance`에서 Java 소스, 기타 텍스트, Swing UI의 글꼴 종류와 크기를 각각 설정하고 저장할 수 있게 한다. 설정은 Windows, Linux, macOS에서 폰트 family 이름이 달라도 안전하게 동작해야 한다.\n\n## 구현 결정\n\n계획서의 미정 항목은 다음과 같이 정해 진행한다.\n\n- 글꼴 선택은 `GraphicsEnvironment.getAvailableFontFamilyNames()`가 반환하는 설치 family 목록으로 제한한다. 콤보박스는 타이핑 검색은 허용하되 임의 이름 입력은 허용하지 않는다.\n- 코드와 기타 텍스트의 기본 글꼴/크기는 현재 테마에서 가져온다. UI 기본 글꼴/크기는 Look and Feel을 설정한 뒤 얻은 `UIManager` 기본값에서 가져온다. 해당 값을 얻지 못하면 각각 `Monospaced` 및 `Dialog`를 사용한다.\n- `ViewerPreferences.fontSize`가 남아 있는 기존 설정에서는 값을 Java 및 기타 텍스트 크기의 초기값으로 복사한다. 새 키가 이미 있으면 새 키를 우선한다. 새 키 저장이 확인되면 옛 키는 더 이상 쓰지 않는다.\n- Ctrl/Meta+휠은 현재 페이지 범주의 글꼴 크기를 변경하고 저장한다. 이미 열린 같은 범주의 페이지에도 새 크기를 적용한다.\n- UI 폰트 family/size 변경은 저장 직후 적용한다. Look and Feel에서 일부 컴포넌트가 갱신되지 않으면 해당 제한을 사용자 문서에 기록하고 재시작 적용으로 전환한다.\n- 본문 글꼴 크기 범위는 기존 2~40을 유지한다. UI 글꼴 크기는 8~32로 제한한다.\n\n## 작업 순서\n\n### 작업 1 — 설정 키, 기본값, 폰트 유틸리티\n\n**담당 범위**\n\n- 새 공통 폰트 설정 helper (구현자가 적절한 패키지에 생성)\n- `services/src/main/java/org/jd/gui/service/preferencespanel/ViewerPreferencesProvider.java`의 설정 키 참조\n- `services/src/main/java/org/jd/gui/view/component/AbstractTextPage.java`의 설정 키 참조\n\n**지시**\n\n1. 다음 키를 한 곳에 정의한다.\n   - `ViewerPreferences.javaFontFamily`, `ViewerPreferences.javaFontSize`\n   - `ViewerPreferences.otherFontFamily`, `ViewerPreferences.otherFontSize`\n   - `ViewerPreferences.uiFontFamily`, `ViewerPreferences.uiFontSize`\n2. AWT에서 사용 가능한 font family 목록을 읽어 정렬·중복 제거하고, Java 논리 폰트(`Monospaced`, `Dialog`)는 목록에 항상 제공한다.\n3. 저장된 family가 현재 런타임에서 없으면 영역별 기본값을 선택한다. 요청 family가 유효한지 `Font` 생성 결과로 검사하고, 잘못된 값은 fallback한다.\n4. 테마 기본 글꼴은 현재 `AbstractTextPage.THEME_RESOURCE`를 적용한 `RSyntaxTextArea`에서 읽는다. UI 기본값은 LAF 적용 후 `UIManager.getFont("Label.font")`를 우선한다.\n5. 기존 `ViewerPreferences.fontSize` 값이 있을 때만 새 Java/기타 크기 키의 기본값으로 사용한다. 새 키가 있으면 기존 값을 덮어쓰지 않는다.\n\n**완료 조건**\n\n- 설정 유틸리티가 특정 OS family를 설치되어 있다고 가정하지 않는다.\n- 값 누락, 미설치 family, 잘못된 크기에도 기본값으로 안전하게 복구한다.\n- 기존 환경설정 파일을 읽을 때 기존 크기가 유지된다.\n\n### 작업 2 — 세 영역 환경 설정 UI\n\n**담당 범위**\n\n- `services/src/main/java/org/jd/gui/service/preferencespanel/ViewerPreferencesProvider.java`\n\n**지시**\n\n1. 기존 단일 크기 입력 UI를 Java source, Other text, UI 세 행/그룹으로 재구성한다.\n2. 각 그룹에 설치 family 목록 콤보박스와 크기 spinner를 배치한다.\n3. Java/Other 크기는 2~40, UI 크기는 8~32로 제한한다.\n4. `loadPreferences`에서 유틸리티 기본값과 저장값을 읽고, `savePreferences`에서 여섯 설정값을 저장한다.\n5. 모든 컨트롤 변경을 기존 `PreferencesPanelChangeListener`에 연결한다. 컨트롤 값은 저장 전에 검증한다.\n6. 환경 설정 대화상자를 닫았다 다시 열어도 선택한 값이 표시되어야 한다.\n\n**완료 조건**\n\n- 세 family와 세 크기를 독립적으로 지정할 수 있다.\n- 지원되지 않는 콤보박스 값이나 범위 밖 크기는 저장할 수 없다.\n- 유효한 설정값에서는 Preferences 확인 버튼이 활성화된다.\n\n### 작업 3 — Java/기타 텍스트 페이지와 gutter 반영\n\n**담당 범위**\n\n- `services/src/main/java/org/jd/gui/view/component/AbstractTextPage.java`\n- `services/src/main/java/org/jd/gui/view/component/JavaFilePage.java`\n- `services/src/main/java/org/jd/gui/view/component/ClassFilePage.java`\n- `services/src/main/java/org/jd/gui/view/component/CustomLineNumbersPage.java`\n- 필요할 때 `DynamicPage` 등 기존 preference 전달 경로\n\n**지시**\n\n1. `AbstractTextPage`가 페이지 설정 범주를 반환하도록 확장한다. `JavaFilePage` 및 `.class` 디컴파일 결과를 보여 주는 `ClassFilePage`는 Java 범주, XML/JSON/Manifest 등은 Other 범주를 사용한다.\n2. `preferencesChanged()`에서 해당 범주의 family와 크기를 적용한다. 화면에 이미 열린 페이지와 새로 생성되는 페이지 양쪽에서 적용한다.\n3. 폰트 적용 시 `RSyntaxTextArea`, `RTextScrollPane`, gutter/줄 번호가 같은 family와 크기를 사용하도록 맞춘다. 기존 줄 번호 현재 행 색상 등 다른 gutter 스타일을 보존한다.\n4. Ctrl/Meta+휠은 현재 페이지 범주의 size 키를 갱신하고, 열린 같은 범주 페이지 모두에 새 크기를 전파한다. 현재 스크롤 위치 유지 동작을 보존한다.\n5. 다른 범주의 family/size는 변경되지 않는지 확인한다.\n\n**완료 조건**\n\n- Java와 기타 텍스트에서 서로 다른 family/size를 표시한다.\n- `.class` 디컴파일 결과는 Java 설정을 사용한다.\n- gutter/줄 번호 글꼴이 본문과 일치하며 글꼴 변경 후 줄 번호 정렬과 접기 아이콘이 유지된다.\n- 설정 적용 직후 현재 열린 페이지와 이후 열 페이지가 동일 설정을 사용한다.\n\n### 작업 4 — Swing UI 전체 글꼴 적용\n\n**담당 범위**\n\n- `app/src/main/java/org/jd/gui/App.java`\n- `app/src/main/java/org/jd/gui/view/MainView.java`\n- `app/src/main/java/org/jd/gui/view/PreferencesView.java`\n- `app/src/main/java/org/jd/gui/controller/PreferencesController.java`\n- 필요한 UI 갱신 helper\n\n**지시**\n\n1. 시작 시 LAF 설정이 끝난 뒤 UI family/size를 `UIManager` 기본값에 반영한다.\n2. 환경 설정 저장 후 UI defaults를 갱신하고 메인 프레임의 자식 컴포넌트에 UI 갱신을 수행한다.\n3. 재생성되는 메뉴, 트리 renderer, 탭, 대화상자, 환경 설정 화면의 글꼴이 같은 UI 설정을 사용하는지 확인한다.\n4. 파생 글꼴의 bold/italic 속성은 유지하되 family/size만 변경한다. 아이콘 크기, 여백, HiDPI 배율을 변경하지 않는다.\n5. 현재 열려 있는 모든 대화상자를 갱신할 수 없다면 열린 설정 화면을 포함한 적용 범위를 정하고, 빠진 부분만 사용자 문서에 명시한다.\n\n**완료 조건**\n\n- UI 설정이 저장 후 재시작 없이 메뉴, 트리, 탭, 메인 화면에 반영된다.\n- UI family/size가 텍스트 페이지 설정과 독립적이다.\n- 레이아웃 잘림, 버튼/메뉴 항목 누락, 다이얼로그 과도한 크기 변화가 없다.\n\n### 작업 5 — 테스트와 회귀 검증\n\n**담당 범위**\n\n- `services/src/test/`의 설정/provider 및 텍스트 페이지 테스트\n- `app/src/test/`의 UI font 적용 로직 테스트 (현재 테스트 구조에 맞게 배치)\n- 관련 사용자 문서\n\n**지시**\n\n1. 설정 기본값, 저장/로드, 이전 `fontSize` 마이그레이션, 잘못되거나 누락된 family fallback을 검증한다.\n2. Java/Other 페이지 범주 결정과 family/size 분리 적용을 검증한다.\n3. Ctrl/Meta+휠이 현재 범주 크기만 변경하고 같은 범주 열린 페이지에 전파되는지 검증한다.\n4. UI defaults 적용과 component tree 갱신 호출을 검증한다.\n5. 기존 파서/인덱싱/하이퍼링크/접기/줄 번호 동작 회귀를 확인한다.\n6. Windows, Linux, macOS에서 각 OS family가 없는 상황을 포함해 기본값 및 폰트 목록을 확인한다. 단일 CI OS만으로 다른 OS 결과를 추정하지 않는다.\n7. 사용자 문서에 세 설정 영역, 사용 가능한 폰트 목록, 적용 시점, 기존 설정 마이그레이션을 설명한다.\n\n**완료 조건**\n\n- 자동 테스트와 기존 검증이 통과한다.\n- Windows/Linux/macOS의 수동 확인 결과가 기록된다.\n- HiDPI, 긴 family 이름, 한글 등 비라틴 문자, fallback에서 표시가 깨지지 않는다.\n\n## 공통 구현 규칙\n\n- 구현은 위 순서를 지키고, 이후 단계가 앞 단계의 미완료 변경에 의존하지 않게 각 작업 완료 시 변경 파일과 검증 결과를 기록한다.\n- 기존 사용자 변경을 덮어쓰거나 되돌리지 않는다.\n- 폰트 이름을 OS별 고정 문자열로 가정하지 않는다. 단, 이식성 있는 기본 family로 `Monospaced`/`Dialog`를 사용한다.\n- 환경 설정 변경은 EDT에서 Swing 컴포넌트와 `UIManager`에 적용한다.\n- Java 코드 출력 파일, 저장한 소스, 인덱스 데이터에는 화면 폰트 설정을 반영하지 않는다.\n\n## 통합 완료 기준\n\n- 세 영역의 family/size 설정이 독립적이고 재시작 후에도 유지된다.\n- 기존 설정의 글꼴 크기 값이 호환성 규칙대로 승계된다.\n- 미설치 family로 인한 예외나 빈 글꼴이 발생하지 않는다.\n- 새 페이지/기존 페이지, gutter, UI가 적용 범위대로 갱신된다.\n- 모든 자동 검증과 OS별 수동 확인 결과를 작업 보고에 남긴다.\n\n## 실행 결과\n\n- **구현 완료**: 영역별 설정 UI, 설정 저장/기존 크기 승계, AWT family 목록과 `Font` 생성 결과 기반 fallback, 범위 밖 크기 저장 방지, Java/기타 텍스트와 줄 번호 적용, Ctrl/Meta+휠 전파, UI 기본값 및 열린 창 갱신, README 사용 안내를 반영했다.\n- **자동 검증**: Windows에서 `./gradlew clean test build`와 후속 `./gradlew test build`가 성공했다. 최신 테스트 결과는 55개이며 실패/오류/건너뜀은 0개다. clean 이후 앱 및 배포 산출물까지 다시 빌드했다.\n- **Windows 화면 확인**: 실제 `PreferencesView`와 `ViewerPreferencesProvider`를 포함한 Preferences 대화상자를 Windows에서 띄워 세 행(Java source, Other text, UI)의 family/size 선택 컨트롤과 확인/취소 버튼이 모두 표시되고 잘리지 않는 것을 확인했다. 확인/취소 동작을 CUA 클릭과 Escape로 조작했지만 화면 상태가 바뀌지 않았다. 별도 Windows QA 하네스에서 실제 `PreferencesView`와 provider를 사용해 버튼 액션을 실행했다. 메모리 설정에서 Java 크기 14를 둔 뒤 Cancel 후에도 14가 유지되고 콜백이 실행되지 않았으며, 다시 열어 19로 바꾸고 OK를 실행하자 19가 저장되고 콜백이 실행됐으며 구형 크기 키가 제거됐다. 따라서 저장/취소 액션은 검증됐지만 사용자의 실제 클릭 입력은 확인되지 않았다.\n- **Linux 런타임 확인**: Ubuntu 22.04 WSL에서 임시로 풀어 둔 OpenJDK 21.0.12.1을 사용해 AWT/Swing probe를 실행했다. AWT family 13개, system LAF `Metal`, `Label.font` `Dialog/12`, 미설치 family의 `Monospaced` fallback을 확인했다. `Dialog`가 한글을 표시하지 못함(`canDisplayUpTo`=0)도 확인했다. sudo 설치 대신 apt 패키지를 `/tmp`에 내려받아 사용했다.\n- **Linux 2x 렌더링 (이전 실행 기록)**: 이전 기록에는 WSL Ubuntu headless Swing에서 466×96 logical pixel 패널의 2x 렌더링을 수행했고, 세 그룹 레이아웃은 유지됐지만 설치 폰트의 한글 글리프가 없어 대체 상자로 표시됐다고 적혀 있다. 현재는 Linux JVM이 없어 렌더링을 재현하지 못했다. README에는 글리프 지원이 호스트에 설치된 폰트에 따른다고 안내한다.\n- **2x Swing 화면 렌더링**: Windows JDK에서 설정 패널을 `sun.java2d.uiScale=2`로 오프스크린 렌더링했다. 435×105 logical pixel 패널 안에 세 그룹의 글꼴/크기 선택이 들어갔고, 2x 이미지에서 Korean `Dialog` 글꼴 샘플이 표시됐다. 긴 family 이름은 고정 prototype 폭을 유지하는 회귀 테스트를 추가했다. 이 렌더링은 실제 디스플레이나 OS UI 검증을 대신하지 않는다.\n- **Linux UI 부분 확인**: 같은 Ubuntu/OpenJDK에서 빌드된 JD-GUI JAR을 격리된 임시 home으로 실제 실행했고, WSL app inventory에 `Java Decompiler (Ubuntu)` 창이 나타났다. CUA가 반환한 창 스크린샷은 다른 앱의 화면을 보여 입력 대상과 맞지 않아 Preferences 대화상자 및 설정 조작은 확인하지 못했다.\n- **macOS 미확인**: macOS 런타임/기기가 현재 작업환경에 없어 실제 UI 및 OS 폰트 목록 확인을 수행하지 못했다.\n\n## 추후 OS별 수동 검증 절차\n\n사용자 요청에 따라 Linux/macOS의 실제 UI 및 OS별 폰트 확인은 후속 작업으로 미뤘으며, 현재 코드 개발 완료를 막는 조건으로 보지 않는다. Windows는 실제 대화상자 화면과 OK/Cancel 액션을 검증했지만 CUA 입력이 전달되지 않아 마우스/키보드 직접 조작은 확인하지 못했다. OS별 후속 검증 시 아래 절차를 사용하고 OS/JDK/Look and Feel/선택 family/결과를 기록한다. UI 변경은 저장되므로 테스트 전후 환경설정 백업을 사용한다.\n\n1. 앱을 실행해 `Help > Preferences... > Viewer > Appearance`를 연다. 환경에 따라 `Ctrl+Shift+P`로 Preferences를 열 수도 있다. 세 영역의 family 선택 목록이 표시되고 현재 런타임의 설치 family를 포함하는지 확인한다.\n2. Java source, Other text, UI에 서로 다른 설치 family와 크기를 지정하고 적용한다. Java 및 `.class` 페이지의 본문/줄 번호, XML 또는 Manifest 페이지, 메뉴·트리·탭·환경 설정 화면이 각자 해당 설정을 쓰는지 확인한다.\n3. Ctrl/Meta+휠을 Java 페이지와 Other text 페이지에서 각각 사용한다. 같은 범주의 다른 열린 페이지 크기는 함께 바뀌고 다른 범주는 그대로인지 확인한다.\n4. 앱을 재시작해 세 영역의 family/size 값이 유지되는지 확인한다. 별도 시험 설정에서 설치되지 않은 family 이름을 저장한 뒤 기본 글꼴로 안전하게 복구되는지도 확인한다.\n5. Retina/HiDPI 배율에서 설정 화면과 코드 줄 번호를 확인한다. OS에 한글 또는 시험할 문자 스크립트 폰트가 설치된 경우 해당 문자가 표시되는지 확인한다. 그 문자를 지원하는 시스템 폰트가 없으면 대체 상자가 나오는 것이므로, 글리프 지원 여부와 앱 오류를 구분해 기록한다.\n6. `Cancel`을 눌렀을 때 시험 설정이 저장되지 않는지 확인한다. 최종 확인 뒤 백업한 환경설정을 복구한다.\n\n\n\n\n\n\n\n\n
